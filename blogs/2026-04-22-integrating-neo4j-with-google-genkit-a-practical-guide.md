See <a href="https://graphrag.com/concepts/intro-to-graphrag/" rel="noopener nofollow" target="_blank">here</a> for more&nbsp;details.</p><p><a href="https://genkit.dev/" rel="noopener nofollow" target="_blank">Google Genkit</a> is an open-source framework that simplifies AI application development through an extensible plugin ecosystem. The Neo4j plugin integrates native vector search with Genkit, allowing documents to be stored as nodes while preserving their traversable relationships. This makes it ideal for GraphRAG pipelines that require both semantic similarity and structural context.</p><p>This guide covers the full integration process, moving from basic semantic search to advanced GraphRAG topologies and persistent chat&nbsp;memory.</p><h2>1. Installation and Prerequisites</h2><p>To get started, you first need to set up your Node.js or TypeScript environment. The integration relies on Genkit&rsquo;s core libraries, the specific Neo4j plugin, an embedding provider (we will use Google AI in these examples), and the official Neo4j JavaScript driver.</p><p>Install the required dependencies:</p><pre class="code CodeMirror cm-s-paraiso-dark">npm install genkit genkitx-neo4j @genkit-ai/google-genai neo4j-driver</pre><p>You will also need a running instance of Neo4j. This can be a local Docker container, a Neo4j Desktop instance, or a cloud-hosted Neo4j AuraDB instance. Ensure your Neo4j version supports vector search (version 5.26+ is recommended, but as we&rsquo;ll see later, version 2026.01+ unlocks even more powerful native filtering features).</p><h2>2. Initializing the Plugin and Connection Configuration</h2><p>Initialize the plugin when creating your Genkit instance. You must provide at least an indexId and an embedder. The plugin acts as a bridge between Genkit&#8217;s abstraction layers and the underlying Cypher queries executed against the&nbsp;graph.</p><pre class="code CodeMirror cm-s-paraiso-dark">import { genkit } from 'genkit';<br />import { neo4j } from 'genkitx-neo4j';<br />import { googleAI } from '@genkit-ai/google-genai';<br /><br />const ai = genkit({<br />  plugins: [<br />    googleAI(),<br />    neo4j([<br />      {<br />        indexId: 'my-vector-index',<br />        embedder: googleAI.embedder('gemini-embedding-001'),<br />      },<br />    ]),<br />  ],<br />});</pre><p>You must specify a Neo4j index and the embedding model you want to&nbsp;use.</p><h3>Managing Connection Credentials</h3><p>You can configure the Neo4j connection in two&nbsp;ways:</p><p><strong>1. The Neo4jParams object allows you to map the Genkit abstractions perfectly to your specific graph&nbsp;schema:</p><ul><li><strong>indexId</strong>: <em>(required)</em> Unique identifier for the vector index. The plugin creates the index if it does not&nbsp;exist.</li><li><strong>embedder</strong>: <em>(required)</em> Genkit embedder used to generate vectors (e.g. Gemini, OpenAI,&nbsp;etc.).</li><li><strong>clientParams</strong>: <em>(optional)</em> Connection details. Falls back to environment variables if&nbsp;omitted.</li><li><strong>label</strong>: <em>(optional)</em> Node label in Neo4j. Defaults to&nbsp;indexId.</li><li><strong>textProperty</strong>: <em>(optional)</em> Property name for the text content. Defaults to&nbsp;text.</li><li><strong>embeddingProperty</strong>: <em>(optional)</em> Property name for the vector. Defaults to embedding.</li><li><strong>idProperty</strong>: <em>(optional)</em> Property for unique document ID. Defaults to&nbsp;id.</li><li><strong>retrievalQuery</strong>: <em>(optional)</em> Custom Cypher RETURN clause to enrich retrieved results.</li><li><strong>searchType</strong>: <em>(optional)</em> Use &#8216;hybrid&#8217; to combine vector and full-text search.</li><li><strong>fullTextIndexName</strong>: <em>(optional)</em> Custom name for the full-text index used in hybrid&nbsp;search.</li><li><strong>searchStrategy</strong>: <em>(optional)</em> Strategy instance. e.g. new MatchSearchClauseStrategy() for native in-index filtering (Neo4j 2026.01+).</li><li><strong>filterMetadata</strong>: <em>(optional)</em> Metadata fields to optimize for fast in-index filtering.</li><li><strong>ragModel</strong>: <em>(optional)</em> LLM used for HyDE and other GraphRAG strategies.</li><li><strong>customGraphRagConfigs</strong>: <em>(optional)</em> Definitions for custom multi-hop GraphRAG topologies.</li></ul><h2>3. Advanced Search: Metadata Filtering &amp; Hybrid&nbsp;Search</h2><p>Semantic search is not a silver bullet. Sometimes, you need exact keyword matches (e.g., searching for a specific product ID like &ldquo;TX-9000&rdquo; where vector distance might yield false positives), or you need to filter results based on strict criteria (e.g., only return documents where status = &#8216;ACTIVE&#8217;).</p><h3>4.1 Metadata Filtering (Neo4j 2026.01+&nbsp;Syntax)</h3><p>The plugin supports advanced metadata filtering, allowing retrieval queries to include structured constraints alongside semantic similarity.</p><p>By using the MatchSearchClauseStrategy, the plugin leverages the new Vector Search syntax introduced in Neo4j 2026.01 (MATCH (n) SEARCH n IN VECTOR INDEX). This enables native in-index filtering, making queries significantly faster. Unlike post-filtering (which retrieves top-K vectors and <em>then</em> filters them, potentially returning zero results), in-index filtering evaluates the metadata conditions <em>during</em> the vector traversal.</p><p>See <a href="https://neo4j.com/blog/genai/vector-search-with-filters-in-neo4j-v2026-01-preview/">this article</a> for more&nbsp;details.</p><p>To optimize performance, you can pass filterMetadata to explicitly instruct Neo4j to build index structures specifically for those&nbsp;fields.</p><pre class="code CodeMirror cm-s-paraiso-dark">import { MatchSearchClauseStrategy, neo4j, neo4jRetrieverRef, neo4jIndexerRef } from 'genkitx-neo4j';<br />import { Document, genkit } from 'genkit';<br />import { googleAI } from '@genkit-ai/google-genai';<br /><br />const customIdx = 'my-filtered-index';<br />const uniqueId = `doc-${Date.now()}`;<br /><br />const ai = genkit({<br />  plugins: [<br />    googleAI(),<br />    neo4j([<br />      {<br />        indexId: customIdx,<br />        embedder: googleAI.embedder('gemini-embedding-001'),<br />        clientParams: "&lt;clientParams&gt;",<br />        searchStrategy: new MatchSearchClauseStrategy(),<br />        filterMetadata: ['department', 'status'],<br />      },<br />    ]),<br />  ],<br />});<br /><br />const newDocument = new Document({<br />  content: [{ text: 'Document without filter metadata configuration.' }],<br />  metadata: { department: 'IT', status: 'active' },<br />});<br /><br />const indexerRef = neo4jIndexerRef({ indexId: customIdx });<br />const retrieverRef = neo4jRetrieverRef({ indexId: customIdx });<br /><br />await ai.index({ indexer: indexerRef, documents: [newDocument] });<br /><br />const docs = await ai.retrieve({<br />  retriever: retrieverRef,<br />  query: 'test query',<br />  options: {<br />    k: 10,<br />    filter: { department: 'IT', status: 'active' }<br />  }<br />});<br /><br />console.log('docs', docs.map(d =&gt; d.content[0].text))<br />/*<br />Result:<br /><br />docs [ 'Document without filter metadata configuration.' ]<br />*/<br /><br /><br /></pre><h3>4.2 Hybrid Search (Vector + Full-Text)</h3><p>Hybrid search blends exact full-text keyword matching with the semantic ranking of vector search. GraphRAG Capabilities: Expanding Context</h2><p>The plugin natively bundles advanced <strong>GraphRAG</strong> strategies. These strategies exploit the connected nature of your graph to provide significantly richer context to the LLM compared to simple vector similarity.</p><h3>Parent-Child Retriever</h3><p>The Parent-Child strategy chunks documents into smaller subchunks for dense, accurate vector matching, but retrieves the broader context (the &ldquo;parent&rdquo; document or chunk) to feed to the&nbsp;LLM.</p><p>Why is this important? Small cohesive text chunks yield the best vector embeddings for exact search, but providing only a tiny sentence to an LLM often results in hallucination due to lack of surrounding context. This strategy fixes that. The plugin provides a specific tool (parentChildIngestor) to automatically ingest data respecting this topology.</p><pre class="code CodeMirror cm-s-paraiso-dark">import { neo4jParentChildRetrieverRef } from 'genkitx-neo4j';<br /><br />async function useParentChildGraphRag(ai: any, userQuery: string) {<br />  const INDEX_ID = 'graphrag-index';<br />  // 1. Ingest Data using the bundled Genkit Tool<br />  // NOTE: Ensure 'llm-chunk' is installed in your project for this tool to work<br />  const ingestorTool = ai.tool(`neo4j/${INDEX_ID}/parentChildIngestor`);<br />  await ingestorTool({<br />    documents: [{ text: "Massive corporate document text...", metadata: { source: "internal" } }]<br />  });<br />  // 2. Retrieve using Parent-Child strategy<br />  const PC_RETRIEVER_REF = neo4jParentChildRetrieverRef({ indexId: INDEX_ID });<br />  const parentDocs = await ai.retrieve({<br />    retriever: PC_RETRIEVER_REF,<br />    query: userQuery,<br />    options: { k: 3 }<br />  });<br />  return parentDocs;<br />}<br /><br />// .. useParentChildGraphRag(..) execution</pre><h3>5.1 Hypothetical Question Retriever (HyDE)</h3><p>HyDE uses the LLM to generate a hypothetical, ideal answer to the user&rsquo;s query first, and then uses that generated text to query the vector space. Genkit Chat Memory with&nbsp;Neo4j</h2><p>Building conversational agents requires managing state. If you pass an infinitely growing list of previous messages to an LLM, you will quickly hit token limits, increase latency, and drive up API&nbsp;costs.</p><p>When initializing the Neo4jSessionStore, you can pass a configuration object to manage credentials and perfectly map the conversational state to your specific graph&nbsp;schema:</p><ul><li><strong>url</strong>: <em>(required)</em> The connection URI for your Neo4j instance (e.g., bolt://localhost:7687).</li><li><strong>username</strong>: <em>(required)</em> The username for Neo4j authentication.</li><li><strong>password</strong>: <em>(required)</em> The password for Neo4j authentication.</li><li><strong>sessionLabel</strong>: <em>(optional)</em> Customizes the node label assigned to the root session node in the graph. Defaults to &#8216;GenkitSession&#8217;.</li><li><strong>messageLabel</strong>: <em>(optional)</em> Customizes the node label assigned to the individual message nodes within a thread. Defaults to &#8216;Message&#8217;.</li><li><strong>nextMessageRelType</strong>: <em>(optional)</em> Defines the cypher relationship type connecting a message to its chronological predecessor (forming the linked list of the chat history). Defaults to&nbsp;&#8216;NEXT&#8217;.</li><li><strong>lastMessageRelType</strong>: <em>(optional)</em> Defines the cypher relationship type that connects the main session node directly to the most recent message (acting as the head of the thread). Defaults to &#8216;LAST_MESSAGE&#8217;.</li></ul><p>The plugin provides a Neo4jSessionStore, establishing a robust Session Persistence layer mapped natively to Neo4j. The module models conversation turns as linked graphs ((:Session)-[:LAST_MESSAGE]-&gt;(:Message)&lt;-[:NEXT]-(:Message)), granting state persistence, easily tunable context limits, and long-term conversation analysis.</p><p>You can use setWindowSize(n) to limit the amount of historical messages injected into the context window, avoiding LLM token bloat while keeping the full history safely stored in the&nbsp;graph.</p><p>Note: setWindowSize(n) defines the number of conversation turns (i.e. pairs of user &#8211; assistant messages) to retain in context. Setting it to 2 on a thread of 6 messages will return the last 4 messages (2 turns &times; 2 messages&nbsp;each).</p><pre class="code CodeMirror cm-s-paraiso-dark">import { Neo4jSessionStore } from 'genkitx-neo4j';<br /><br /><br />async function startPersistentChat(ai: any, sessionId: string, userMessage: string) {<br />  <br />  // 1. Initialize the Neo4j backed session memory<br />  const neo4jStore = new Neo4jSessionStore({<br />    url: '&lt;connection URI&gt;',<br />    username: '&lt;username&gt;',<br />    password: '&lt;password&gt;',<br />  });<br />  <br />  // 2. You can also programmatically clear a user&rsquo;s session&nbsp;history.</p><pre class="code CodeMirror cm-s-paraiso-dark">import { Neo4jSessionStore } from 'genkitx-neo4j';<br /><br />async function manageChatSessions() {<br />  <br />  // Custom schema configuration<br />  const customStore = new Neo4jSessionStore({<br />    url: 'bolt://localhost:7687',<br />    username: 'neo4j',<br />    password: 'password',<br />    sessionLabel: 'AppSession',          // Defaults to 'GenkitSession'<br />    messageLabel: 'ChatMessage',         // Defaults to 'Message'<br />    nextMessageRelType: 'THREAD_NEXT',   // Defaults to 'NEXT'<br />    lastMessageRelType: 'THREAD_HEAD'    // Defaults to 'LAST_MESSAGE'<br />  });<br />  const sessionId = 'user-123-session';<br />  // Programmatically clear/delete all messages and relationships for a session<br />  await customStore.clear(sessionId);<br />  console.log(`Session ${sessionId} has been wiped.`);<br />}<br /><br />// .. manageChatSessions(..) execution</pre><h3>6.1 Manual Session Management</h3><p>Sometimes, passing the store directly to ai.chat() isn&#8217;t enough.
