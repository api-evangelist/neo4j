<div><img alt="" class="attachment-large size-large wp-post-image" height="366" src="https://dist.neo4j.com/wp-content/uploads/20260428043318/1lEEXavEBpO6PA9kvACSlsw.png" style="margin-bottom: 15px;" width="640" /></div><h2>The next release of <strong>Neo4j</strong> introduces a feature we have been developing for some time and are now making publicly available: asynchronous I/O&nbsp;support.</h2><h3><strong>Why Asynchronous I/O&nbsp;Matters</strong></h3><p>Historically, Neo4j has relied on synchronous I/O throughout the system. This means that every read or write was a blocking operation: the executing thread had to wait for the operating system to complete the request before it could continue. While this model is simple and predictable, it can introduce significant waiting time, particularly in cloud environments where I/O latencies tend to be&nbsp;higher.</p><figure><img alt="" src="https://dist.neo4j.com/wp-content/uploads/20260428043318/1lEEXavEBpO6PA9kvACSlsw.png" /><figcaption>Async IO between application and OS&nbsp;kernel</figcaption></figure><p>Asynchronous I/O addresses this limitation by allowing multiple requests to be issued concurrently while the program continues execution and is notified on completion. For workloads that perform large numbers of I/O operations and do not need to wait for each individual operation to complete, this approach can deliver substantial performance improvements.</p><h3>What we&rsquo;re releasing</h3><p>While asynchronous I/O is still at an early stage within Neo4j, we are ready to share the first parts of this work. Even in its initial form, it has the potential to deliver meaningful performance improvements for certain type of workloads, particularly in cloud environments where storage latency and concurrency characteristics can make non-blocking I/O especially valuable.</p><p>In this first iteration, async I/O support was added to the background page evictor&#8202;&mdash;&#8202;which frees pages from the page cache when the cache becomes full&#8202;&mdash;&#8202;and to the checkpointer, which flushes all modified pages from memory to storage. This is only the beginning. Future versions may extend async I/O support to additional parts of the database, gradually expanding where Neo4j can take advantage of asynchronous storage operations.</p><h3><strong>Getting started with asynchronous I/O in&nbsp;Neo4j</strong></h3><p>In 2026.04, Neo4j takes an important step toward modernizing I/O handling by introducing <a href="https://en.wikipedia.org/wiki/Io_uring" rel="noopener nofollow" target="_blank"><strong>asynchronous I/O</strong> using <strong>io_uring</strong></a> on Linux, which uses a combination of ringbuffers to manage the I/O requests.</p><p>In synchronous mode each I/O would block execution until it completed, limiting throughput and leaving available I/O bandwidth underutilized and threads blocked. With asynchronous I/O, Neo4j can now issue requests without waiting, allowing other work to continue and making better use of system resources enabling higher throughput.</p><p>This initial delivery enables the <strong>background page evictor</strong> and <strong>checkpointer</strong> to take advantage of async I/O when available and configured. While still in its early stages, these components demonstrate the potential of non-blocking execution to improve database performance, particularly in cloud and high-latency environments.</p><h3>Prerequisites</h3><p>Asynchronous I/O is <strong>not enabled by default</strong> and requires a few conditions to be&nbsp;met:</p><ul><li>Neo4j <strong>Enterprise Edition</strong></li><li>Linux operating system</li><li><strong>liburing</strong> library installed</li><li><strong>JDK 25 or&nbsp;later</strong></li></ul><p>To verify whether Neo4j can leverage the underlying asynchronous I/O capabilities, you can check the diagnostics in the debug logs. When the system is able to use the io_uring provider, you will&nbsp;see:</p><p><em>Native async IO provider: IOUring based async provider is available.</em></p><p>If any of the required conditions are not met, the log will instead&nbsp;show:</p><p><em>Native async IO provider: async IO provider is not available.</em></p><p>This provides a quick way to confirm whether asynchronous I/O is active and ready for use in your environment.</p><h3>Configuration</h3><p>To enable asynchronous I/O in Neo4j, set the following <a href="https://neo4j.com/docs/operations-manual/current/configuration/configuration-settings/#config_server.memory.pagecache.async">neo4j&nbsp;setting</a>:</p><pre class="code CodeMirror cm-s-paraiso-dark">server.memory.pagecache.async=true</pre><p>Once enabled and all prerequisites are met, the <strong>background page evictor</strong> and <strong>checkpointer</strong> will switch to async mode. In this mode, Neo4j can perform significantly more I/O concurrently, improving efficiency and throughput.</p><p>Even while operating asynchronously, configured checkpoint limits such as db.checkpoint.iops.limit or db.checkpoint.throughput.limit are still respected. This allows you to safely experiment with these settings and optimize them for your environment.</p><p>With these new asynchronous capabilities, it&rsquo;s also a good opportunity to reconsider whether the page cache could benefit from <strong>Direct I/O</strong>&nbsp;using:</p><pre class="code CodeMirror cm-s-paraiso-dark">server.memory.pagecache.directio=true</pre><p>Direct I/O may not be suitable for all workloads, but if your Neo4j page cache is large enough to cover the entire database store, now could be a good time to revisit this option and evaluate potential performance improvements.</p><h3>Metrics</h3><p>When asynchronous I/O is configured and active, all existing metrics continue to work as before. In addition, several new metrics have been introduced specifically to track the asynchronous I/O operations.</p><figure><img alt="" src="https://dist.neo4j.com/wp-content/uploads/20260428043302/1bCT-jNMBAuPITeVLRoKOew.png" /></figure><p><strong>Summary</strong></p><p>This release marks the beginning of a broader journey to bring asynchronous I/O deeper into Neo4j, unlocking improved concurrency, higher throughput, and greater efficiency for future versions.</p><p>It introduces a completely new way for Neo4j to handle I/O, representing a significant milestone in what the database is capable of. Beyond the components enabled today, this lays the foundation for expanding asynchronous I/O to additional parts of Neo4j in future releases, opening the door to even greater performance and scalability.</p><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=4fdf094a9794" width="1" /><hr /><p><a href="https://medium.com/neo4j/introducing-asynchronous-i-o-in-neo4j-using-io-uring-4fdf094a9794" rel="noopener nofollow" target="_blank">Introducing Asynchronous I/O in Neo4j using io_uring</a> was originally published in <a href="https://medium.com/neo4j" rel="noopener nofollow" target="_blank">Neo4j Developer Blog</a> on Medium, where people are continuing the conversation by highlighting and responding to this story.</p>
